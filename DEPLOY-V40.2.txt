VEEB RESOLVER V40.2 STARTUP TELEMETRY

PURPOSE
This is a deliberately conservative follow-on to V40.1. It keeps the V40.1
source acquisition, progressive WebM, FFmpeg, priority/preemption and cache
architecture intact while making the 2-3 second playback startup target
measurable and resolver failures traceable.

COMPATIBILITY
- Compatible with the existing V40.1 Cloudflare Worker.
- No Worker change is required to deploy this resolver release.
- The existing Worker will ignore the new startup headers until it is upgraded
  to consume them.
- Rollback is simply redeploying the previous V40.1 package.

CRITICAL PATHS INTENTIONALLY NOT CHANGED
- Authenticated mweb remains the first eligible foreground route.
- POT / anonymous / auth fallback ordering is unchanged.
- Extraction startup remains serialized.
- Progressive direct-audio WebM still begins after the existing 8 KiB source
  publication rule.
- VEEB_MP3_STARTUP_MIN_BYTES still defaults to 4096.
- MP3 remains 128 kbps by default.
- FFmpeg reconnect settings are unchanged.
- Foreground/background concurrency and preemption rules are unchanged.
- R2 completion still requires a finite validated MP3.

NEW IN V40.2
1. Startup timing for every MP3 job:
   - queueMs
   - sourceAcquireMs
   - encoderStartupMs
   - totalStartupMs

2. Successful stream responses now include:
   X-Veeb-MP3-Job
   X-Veeb-Startup-Queue-Ms
   X-Veeb-Startup-Source-Ms
   X-Veeb-Startup-Encoder-Ms
   X-Veeb-Startup-Total-Ms
   X-Veeb-Startup-SLA-Ms
   X-Veeb-MP3-Startup-Bytes

3. Playback startup SLA logging. Default target:
   VEEB_PLAYBACK_START_SLA_MS=3000

   Render logs emit either:
   v40.2 playback startup ready
   v40.2 playback startup slow

   with the per-stage timing breakdown.

4. Protected job diagnostics:
   GET /job/{jobId}
   Authorization: Bearer <RESOLVER_SECRET>

   This returns safe job state, bytes produced, last-output age, startup timing,
   source path/client, redacted attempts and terminal error. It deliberately
   does not return source media URLs or credentials.

5. Explicit stream failure codes:
   MP3_STARTUP_TIMEOUT
   MP3_STARTUP_EMPTY
   MP3_OUTPUT_STALLED
   FFMPEG_FAILED

   VEEB_MP3_OUTPUT_STALL_TIMEOUT remains 20 seconds by default, matching V40.1
   behaviour. V40.2 makes it configurable and observable rather than silently
   changing the threshold.

6. YouTube "Video unavailable" is now distinguished from route/auth failure as:
   SOURCE_VIDEO_UNAVAILABLE

   Region-specific unavailability is:
   SOURCE_REGION_RESTRICTED

   V40.2 still tries the existing configured routes before declaring the final
   per-track unavailable result. It does not prematurely skip the fallback tree.

RECOMMENDED RENDER SETTINGS
Keep the existing known-good V40.1 concurrency settings initially:
  VEEB_MP3_MAX_CONCURRENT=3
  VEEB_MP3_MAX_BACKGROUND=2

New optional settings. Defaults shown:
  VEEB_PLAYBACK_START_SLA_MS=3000
  VEEB_MP3_OUTPUT_STALL_TIMEOUT=20

Do NOT tune these until production startup logs have been collected.

IMPORTANT FOR THE 2-3 SECOND TARGET
The Render service must be continuously available. A sleeping/cold-starting
instance cannot reliably satisfy a 2-3 second click-to-audio target. The supplied
render.yaml still identifies the free-plan cold-start risk and has not been
silently changed to a paid plan.

DEPLOY
1. Keep a copy of the currently deployed V40.1 release for immediate rollback.
2. Deploy this package with the SAME resolver secrets, cookie file and existing
   concurrency settings.
3. Call /health with the resolver bearer secret and confirm:
     version = v40.2-startup-telemetry
     playbackStartSlaMs = 3000
     startupTelemetryEnabled = true
     mp3StartupBytes = 4096
4. Play several genuinely uncached tracks.
5. Inspect Render logs for "v40.2 playback startup ready" and
   "v40.2 playback startup slow".
6. For a returned X-Veeb-MP3-Job value, GET /job/{jobId} immediately after a
   problem to inspect the exact resolver-side state.
7. Do not change buffer size, source ordering or timeouts based on one track.
   Tune only after the stage timings show a repeated bottleneck.
