VEEB RESOLVER V40.1 PRIORITY/PARALLEL CACHE

This release is designed to pair with veeb-worker-r2-priority-parallel-v40.1.txt.

WHAT CHANGED
- X-Veeb-Purpose=playback is foreground.
- r2-background-prefetch, r2-next-prefetch, r2-library-warm and cache-fill are background.
- Background jobs may run in parallel, but cannot consume every configured slot.
- If foreground arrives while all slots are occupied, the newest active background job is cancelled and foreground is admitted.
- Source-download and FFmpeg capacity have the same foreground reservation. This is not merely an HTTP-level priority flag.
- /health reports active foreground/background jobs, limits and preemption count.
- /completed remains read-only and never starts acquisition.

RECOMMENDED STARTING RENDER SETTINGS
  VEEB_MP3_MAX_CONCURRENT = 3
  VEEB_MP3_MAX_BACKGROUND = 2

That means up to two background cache fills while idle, with one slot always unavailable to new background jobs. If foreground demand fills total capacity, a background job can be preempted so playback wins.

If the actual Render instance is CPU constrained, start instead with:
  VEEB_MP3_MAX_CONCURRENT = 2
  VEEB_MP3_MAX_BACKGROUND = 1

Do not set VEEB_MP3_MAX_BACKGROUND equal to VEEB_MP3_MAX_CONCURRENT. The resolver clamps background to at most total-1 so at least one foreground lane always remains reserved.

DEPLOY
1. Replace the current resolver repository contents with this package, preserving existing Render secrets and cookie secret file.
2. Set the two environment variables above. Recommended first test is 3 / 2.
3. Deploy and call /health with the resolver bearer secret. Confirm:
     version = v40.1-priority-cache
     maxConcurrentTranscodes = 3
     maxBackgroundJobs = 2
     foregroundReservedSlots = 1
4. Deploy the companion Cloudflare Worker v40.1.
5. Watch /health -> jobs while background warming is active. activeBackground can reach 2. A cold playback request should appear as activeForeground and backgroundPreemptions may increase if it arrived at full capacity.

The Worker still avoids starting new library warm jobs while it believes a cold foreground playback is active. Resolver priority is the hard second line of defence for races and multiple users.
