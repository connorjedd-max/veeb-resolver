RESULTS

codecSelfTest.ok=true:
  The actual Render encoder produced valid MP3 from a local synthetic source.
  This is not proof that YouTube source access works.

cookieSessionTest.youtubeReportsLoggedIn=true:
  YouTube reported page-level login with the supplied cookie jar.
  Media-download permission remains a separate check.

cookieSessionTest.youtubeReportsLoggedIn=false:
  YouTube reported logged out for this request. Refresh the cookie export.
  The flag cannot distinguish expiry, revocation or another session issue.

cookieSessionTest.youtubeReportsLoggedIn=null:
  Login state could not be established. Read status/error. This is NOT a failed
  authentication verdict and is not proof the cookies are valid either.

attempts includes fg-mweb-auth, usesCookies=true:
  Cookie-backed mweb was actually attempted. Its stage and code show whether
  extraction was challenged or the selected media download was refused.

mp3Complete=true:
  The entire MP3 passed resolver validation. The unchanged Worker then performs
  its R2 store/readback test. Confirm that separately in r2Stored/r2Read.

The authenticated source-download fallback waits for source download before
encoding. Direct streaming remains available for a source that permits it.

Do not send cookie values in chat or commit them to GitHub. The README includes
fresh-export instructions. A readable cookie file is not a verified session.
